01

What we found

From your brief, the account already has custom conversions and they fire, so the problem is not missing tracking. The problem is that the conversion carries no price. Three gaps usually cause this, and all three are fixable without rebuilding the account.

1. Custom conversions built on a URL rule cannot read the order total

High impact

Most custom conversions are set to fire when someone lands on a thank-you or confirmation page. That rule knows a purchase happened. It has no way of knowing how much was paid. At best it holds one fixed value for every sale, which is why Ads Manager shows a count but no real purchase value.

Fires on page visit onlyFires with the order data attached
No value, or one fixed value for all salesDynamic value and currency per order
Ads Manager shows results, no revenuePurchase conversion value and ROAS columns populate
Cannot optimize toward high value buyersValue based optimization becomes possible

2. In fitness and lifestyle, checkout often happens on another platform

High impact

Class packs, memberships and products are often sold through a booking or store platform such as Mindbody, Squarespace Commerce or Shopify. When the sale completes there, the Pixel on the main website never sees the price. The value has to come from the platform that holds the order, through its native Meta integration, a data layer, or a server side feed.

3. Browser only tracking and analytics will not agree

Medium impact

If value is only sent from the browser, ad blockers and iOS privacy settings drop part of the sales. Your analytics system then shows different revenue to Ads Manager, and nobody trusts either number. Matching both to the same order data closes that gap.

The 30 day plan

Most of the build lands in the first two weeks. The last two weeks prove the numbers match real sales before anyone relies on them.

1

Audit the current setup

Review Events Manager, every custom conversion and its rule, the Pixel and any GTM container, and walk the full checkout to see exactly where the order completes.

Why: the right fix depends on which platform holds the order total.

2

Send a standard Purchase event with dynamic value and currency

Use the platform's native Meta integration where it passes value, or pull the order total from a data layer through GTM. Then rebuild the custom conversions on top of the Purchase event instead of a URL.

Why: this is the step that puts the price into Ads Manager.

3

Add Conversions API with event ID deduplication

Send a server copy of each purchase with the same event ID and customer match keys, and check the Event Match Quality score.

Why: recovers sales the browser misses without counting any sale twice.

4

Match the value into your analytics system

Send the same purchase value to GA4 and set consistent UTMs on every Meta ad so revenue lines up by campaign.

Why: one revenue number across Ads Manager and analytics.

5

Verify, reconcile and hand over

Test in Events Manager, add Purchase conversion value and ROAS columns to a saved report, compare a week of attributed sales against the platform's own sales report, and leave a short written guide.

Why: the client sees proof that the numbers are real.
